Cowork lets Claude work on your files and run long tasks inside a Linux virtual machine. On Linux it runs in one of two places:

Cloud VM (default)Local VM (opt-in)
Where it runsAnthropic's serversYour PC, with KVM
SetupNoneCOWORK_LOCAL=on
NeedsInternetKVM, vhost_vsock, ~2–4 GB free RAM
Your filesSynced to the folders you chooseShared directly with virtiofs

Use Cowork (cloud)

Open the Cowork tab, pick a folder, and give Claude a task. Nothing else is needed.

Run the Cowork VM on your own computer

  1. Allow KVM and load the vsock module: 
    sudo usermod -aG kvm $USER          # log out and back in afterwards
sudo modprobe vhost_vsock
  2. Add to ~/.config/claude-desktop-flatpak/settings.conf: 
    COWORK_LOCAL=on
  3. Restart Claude. The first start downloads the VM image (a few hundred MB).

What this changes: Cowork's helper talks to its VM over a vsock socket, which Flatpak blocks for all apps. With COWORK_LOCAL=on the helper and QEMU run outside the Flatpak sandbox (in a small bubblewrap container using the QEMU, OVMF firmware and virtiofsd bundled in the Flatpak). That is why it is off by default.

Check that the local VM runs

pgrep -a qemu-system || echo "no VM running"

Memory and CPU

Claude starts the VM when you open a Cowork session – including when the app reopens one you left open – and stops it only when you quit Claude. It currently reserves 4 GB and typically uses about 1.4 GB and a few percent of one CPU core while idle. To get the memory back, switch to Chat and quit Claude; next time it opens on Chat and no VM starts.

Troubleshooting

  • “Workspace unavailable” / falls back to the cloud: check COWORK_LOCAL=on, the kvm group (log out and in) and lsmod | grep vhost_vsock.
  • Cowork disappeared after an update: the app starts unpatched if a new Claude version doesn't fit the Cowork patch; the next update restores it.
  • Turn Cowork's patch off completely: COWORK=off runs the untouched app.
