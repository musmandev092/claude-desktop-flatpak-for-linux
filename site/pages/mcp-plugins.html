Flatpak apps live in a sandbox that normally can't see your node, python or docker. This Flatpak includes a bridge, so every local MCP server and every Claude Code command runs with your real tools – on the host, or inside a toolbox – with no changes to the configs you already use.

Where the config lives

~/.var/app/io.github.musmandev092.ClaudeDesktop/config/Claude/claude_desktop_config.json

Or open it from Claude: Settings → Developer → Edit Config.

Examples

{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "/home/you/Projects"]
    },
    "time": { "command": "uvx", "args": ["mcp-server-time"] },
    "github": {
      "command": "docker",
      "args": ["run", "-i", "--rm", "-e", "GITHUB_PERSONAL_ACCESS_TOKEN", "ghcr.io/github/github-mcp-server"],
      "env": { "GITHUB_PERSONAL_ACCESS_TOKEN": "…" }
    }
  }
}

API keys in env reach the server, and never appear in the process list.

Host or toolbox

By default commands run on your host. To run them in a toolbox (recommended on Silverblue, Kinoite, Bazzite), put this in ~/.config/claude-desktop-flatpak/settings.conf and restart Claude:

TOOLBOX=dev

For one server in a different toolbox, or a command given by absolute path, use host-run:

"command": "host-run",
"args": ["--toolbox", "other-box", "/home/you/.local/bin/my-mcp-server"]

Claude Code

Claude Code sessions, its shell commands and the built-in terminal use the same bridge: your login shell, your git config and SSH keys, your language runtimes. Nothing needs to be installed inside the Flatpak.

Troubleshooting

  • “command not found” for a tool you just installed: restart Claude – the list of commands is refreshed at start.
  • A server hangs on start: run the same command in a terminal (in the toolbox if you use one) to see its error; the first npx -y run downloads packages and can take a while on slow internet.
  • Logs: ~/.var/app/io.github.musmandev092.ClaudeDesktop/config/Claude/logs/mcp*.log

Performance

A command reaches your toolbox in about 40 ms, and messages between Claude and a running MCP server take well under a millisecond. The bridge is tested with 10,000 generated scenarios – binary data, 16 MB pipes, 80 parallel commands, signals and broken settings – and 20 security tests.
